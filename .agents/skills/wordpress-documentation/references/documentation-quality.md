# Documentation Quality

Check whether a new maintainer can understand: purpose/features, prerequisites, setup, development/build commands, project structure, theme/plugin/MU-plugin ownership, important conventions, deployment/maintenance notes, and non-obvious architecture decisions.

For code docs, add comments/docblocks where contracts, side effects, complex logic, or public APIs benefit; remove stale/obvious commentary. Verify commands/paths against the repository before documenting them.
