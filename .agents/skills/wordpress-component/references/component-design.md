# Component Design

- Give the component one clear responsibility.
- Prefer explicit inputs/arguments over hidden globals where practical.
- Reuse existing template-part/component conventions.
- Keep business/data-fetching logic outside presentational markup when it improves reuse/testability.
- Co-locate or clearly associate styles/scripts using the project's existing structure.
- Avoid abstractions that make a one-off component harder to understand.
